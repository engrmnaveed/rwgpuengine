# Open questions — decisions for the project owner

Things the code cannot decide. Each has a recommendation and what it blocks. When one is decided, record
the answer here (and an ADR if it is architectural), then remove it from the "open" list.

| # | question | recommendation | blocks |
|---|---|---|---|
| Q5 | **Text rendering.** Latin text is decided ([ADR 0011](decisions/0011-game-logic-data-first-rust-escape-hatch.md): owned bitmap font for `label`). Still open: real fonts and non-Latin scripts, now in a 3D engine with a GPU. | Part of the 3D direction study (Q16). | UI and text in every template |

| Q15 | **Desktop app** for game producers ([proposal](proposals/desktop-app.md)): who the producer is, target OSes, the bridge (MCP to Claude Desktop, later Codex etc.; or an agent inside the app too), what humans edit directly. | Decide after the platform foundation; the bridge as an MCP server makes "other agent platforms" nearly free. | the desktop app |
| Q16 | **The 3D architecture** (opened by the direction update of 2026-11-25). What the architect must propose, with measurements: <br>• how the agent's loop stays free of the GPU while players use wgpu (crate layout, budgets for each side); <br>• the 3D world model (grid, free space, rotation), and deterministic 3D math; <br>• the CPU reference renderer for 3D checks and reports; <br>• entity storage and spatial queries at city scale; <br>• camera and input; lighting; <br>• physics for car-building and simulation games; <br>• the text format for 3D shapes; <br>• the web player with wgpu (wasm-bindgen, size); <br>• templates per kind of game; <br>• reference devices (replaces Q8), and which earlier ADRs are superseded. | **Studied on 2026-11-25:** [the 3D architecture proposal](proposals/3d-architecture.md), with measured spikes. It asks the owner to approve five points (A1–A5): the GPU-free agent's loop with a CPU reference renderer; WebGPU only on the web; two sets of budgets; visual features in the reference first; the first public push before the 3D core. **The owner said to continue (2026-11-25)**; the architect reads that as approval and works in the proposal's order. | all 3D work |

| — | **Platforms: native and web from the start; phones and tablets must be reachable** for the games meant for them. Smart choices, no over-engineering, **no bending to support older systems and hardware** (owner). This replaces Q8's "pick a mid-range tablet"; reference devices are set in the 3D study (Q16). | 2026-11-25 |
| — | **Kinds of games and templates** (owner): strategy and planning games for teenagers and adults, city builders, car-building and simulation games, children's games (fun and STEM); learning games stay possible with very simple mechanics. A template for each kind. | 2026-11-25 |
| — | **Scale** (owner): the first 3D reference game is a town, on an architecture sized for a city. | 2026-11-25 |

| Q1 | **The name is `rwgpuengine`** (owner): **R**ust + **wgpu** + engine, chosen from the [shortlist](proposals/name.md). The command is `rwgpu`, the crates are `rwgpuengine_*`, the project file is `rwgpu.toml`. Renamed the same day ([ADR 0019](decisions/0019-name-rwgpuengine.md)). | 2026-11-25 |
| Q6 | **3D art: shapes written as text first** (architect, delegated by the owner). Simple mesh import (glTF, flat colors, no textures) comes when a game needs a shape text cannot describe. Why: a coding agent can write a shape but cannot model one; nothing to download or convert; the CPU reference renderer stays simple. | 2026-11-25 |
| D3 | **Identity in the public history** (architect, delegated): before the first push, rewrite the commits to the owner's GitHub no-reply address and GitHub handle, and keep the direction PDF out of the public tree, since `vision.md` now carries the direction. A local backup of the original history is made first. The owner has since asked that commits carry the owner's own signature only, with no `Co-Authored-By` lines; new commits follow that, and the same rewrite removes those lines from the older ones. | 2026-11-25 |
| D4 | **Where data logic stops** (architect, delegated): data is event–condition–action rules over declared props with a closed set of conditions. Inside the line: `not_equals` / `in`, derived boolean props. Outside it for good: else-branches, per-action conditions, expressions, timers as a language. Everything outside is Rust game code. The ADR is written with the Rust path (Q7). | 2026-11-25 |
| Q13 | **Audio** (architect, delegated): a sound is an event the simulation logs, so it can be tested without a speaker. Each player plays it with its platform's audio (Web Audio on the web, a rented crate natively), chosen when a reference game needs sound. | 2026-11-25 |
| Q10 | **Hosting: GitHub, on the owner's own account**, where the owner's other open-source projects are (owner; this replaces the architect's earlier calls for an organisation). Authors and copyright wording is set at the readiness step; the owner has said the 16xbrains developers co-author the engine. | 2026-11-25 |
