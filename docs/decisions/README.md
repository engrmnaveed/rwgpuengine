# Architecture decision records

One file per decision: context, decision, consequences, and **when to revisit**. Decisions are changed by
adding a new ADR that supersedes the old one (and marking the old one), never by silently editing.

> **The name.** Until 2026-11-25 the engine had the working codename "slate". ADRs 0001–0018 were written
> then and keep that name: read `slate` as `rwgpu`, `slate_core` as `rwgpuengine_core`, `slate.toml` as
> `rwgpu.toml` ([ADR 0019](0019-name-rwgpuengine.md) has the full table).

| [0025](0025-rwgpu-export-web.md) | **`rwgpu export web`** writes a project as a folder any static web host can serve: the page, the player and the game, the files `rwgpu serve` serves, every address relative; the WebGPU player when one is found (one lookup with `serve`), else the CPU player, E0008 when neither; the bundle holds only what the engine reads; validated first, deterministic, no path of the machine; `rwgpu serve --site`; `cargo xtask ci` plays every example exported with the CPU player from a static server, `cargo xtask gpu` every example exported with the WebGPU player in a headless Chrome, at `/` and under `/rwgpuengine/`. **Hosting: GitHub Pages from this repository** (the owner, 2026-11-26), by a manual-only workflow that proves the folder it publishes | accepted, built |
| [0026](0026-cell-index-and-the-world-in-modules.md) | The simulation at scale, piece 1: a **cell index** beside the entities (the ground's cells as an array of list heads, lists in id order, a sorted map outside; a 24-byte fact per entity; lists of who has each behavior; copies per prefab; routes from a signal to its connections), so **no rule looks at every entity**; derived, not hashed, kept right by the rules and by a guard on `World::get_mut`, and held to the scans (`world/scan.rs`) by an oracle of 17 generated worlds, 16,000 random steps and a rebuild check in debug builds. One step with 50,000 actors: 2,659 → 14.1 ms, 0.88 ms without the event log. Entities stay fat: columns measured (1.4 times faster at 50,000, 2.5 times at 500,000) and left for a game at city scale. `world.rs` in modules | accepted, built; the 2 ms budget row came with [0027](0027-events-at-scale-and-limits-on-work.md) |
| [0027](0027-events-at-scale-and-limits-on-work.md) | The simulation at scale, piece 2: **events at scale** — in a step, the first 256 `moved`, `blocked` (for moves), `trigger` and `custom` events of each kind are written and the rest counted (an `omitted` event says how many); **watching** writes all of an entity's or a kind's events (`--watch` on `run` and `inspect`, `inspect --entity --events`, a playtest's `[[expect]]` names); every other kind is always written. Measured against writing every event, writing a fact and the sentence on reading, the budget alone and watching alone. **Limits on the work of a step** in one table (`rwgpuengine_core::limits`): 1,000 signals, 10,000 actions, 10,000 count changes, 1,000,000 entities, 256 taps, each with a code (E0301 to E0305), a diagnostic and an event; counts looked at per prefab. One step with 50,000 actors: 14.1 → 1.06 ms; budget row `time.sim_step_us` = 2,000. Small games' events unchanged, byte for byte | accepted, built |
| [0028](0028-loader-as-a-pipeline-linear-and-limits-on-sizes.md) | The loader at scale, piece 3: **`load/` as a pipeline** (parse, resolve, check, build; each problem carries its place in the file and the stages' lists are merged, so the order agents read is unchanged); **linear** (one index of names per scene, a map of cells, sets, defaults read without the parser, an exact faster "did you mean"): `rwgpu check` of 50,000 actors 1,635 → 79 ms, budget 250 ms; **limits on a project's sizes**, E0209, each measured (a file, a scene's entities, a ground's cells, cells covered, prefab bytes copied, a name's length, a playtest's tables). An oracle of 474 cases pins everything the loader says | accepted, built; one question for the owner inside (hints for many unknown names) |

| [0030](0030-camera-over-the-ground-and-by-touch.md) | Step 6, piece 2: **the camera's center stays over the ground** (`Session::camera_bound`: the ground's cells, else what the world holds at the start, and always the scene's own camera; fixed at the start, reported with the camera, kept by every move, no format key), and **every camera move by touch alone** in both players: one finger pans in a game with no mover (swipes with one), two fingers grab the ground (pan, zoom about their midpoint, a twist of 20° turns and settles on a quarter turn), a tap of two fingers switches the view, of three goes home; buttons under the page's frame. The thresholds measured on 4,000 modelled gestures per drift; the browser check touches the page through DevTools and `rwgpu run` replays what it recorded to the same state and camera | accepted, built; not tested on a real touch screen |
